## 背景・課題

職場の同僚との飲みの場で「いい店があったら共有したい」という話になったことがきっかけ。
既存のサービスではお気に入りのお店を身内で手軽に共有・検索する体験が十分に実現できていない。

### 既存サービスの課題

| サービス | 課題 |
|----------|------|
| Googleマップ | 保存したもののリストが使いづらい |
| 食べログ | 個人の記録に留まり、他者との共有がしにくい |
| Instagram | お店情報の保存がしにくく、検索性が悪い |
| その他アプリ | UIや成熟度の面で使う気になれない |

## 実現したいこと

身内（職場の同僚やプライベートの友人）の間で、お気に入りの飲食店を**簡単に登録・共有・検索**できるアプリを作りたい。

- Googleマップ等のリンクからお店を**その場でサッと登録**できる（忘れる前に）
- 手動入力の場合: 店名、大体のエリア、食事のジャンル、飲み物のジャンル、コメント、写真、おすすめメニュー
- **飲み物のジャンル**と**料理のジャンル**で簡単に探せる
- **Discordのようなグループ**単位で共有し、複数グループに参加できる
- **ランク**をつけられる（点数方式ではなく）
- **「行った」リスト**をグループで共有
- **「行きたい」リスト**を個人で保存
- 新しいメンバーがグループに入ったとき、過去のお店情報も全部見られる

## 対象ユーザー

- **年齢層**: 20代〜40代
- **ITリテラシー**: 高め（IT企業勤務が中心）
- **グループ規模**: 基本4〜5人、部署利用で10人以上の可能性も
- **利用範囲**: 身内（同僚・友人）のみ。一般公開は予定なし

## ユーザーストーリー

- いい店を見つけた → **その場でサッと登録**したい（忘れるので）
- 「今日飲みに行こう」→ アプリを開いて**ジャンルやエリアで探したい**
- 「あの店行ったことあったっけ？」→ **行ったお店リストを検索して確認**したい
- 新メンバーがグループに参加 → **過去のお店情報も全部見られる**

## 期待する効果

- 「あの店行ったことあったっけ？」がなくなる
- 行ったことがあるお店リストを簡単に検索できる
- 行きたいお店を個人で保存しておける
- コミュニティでお店の話題で盛り上がれる

## 制約・条件

- **スマホアプリは必須**。Webアプリはあると嬉しいが優先度低
- Macを所有していないため**Swiftでの開発は不可**（Flutter or Kotlin Multiplatform）
- **Kotlinバックエンド**を試してみたい
- バックエンドAPIとクライアント側は**分離したアーキテクチャ**にしたい
- **AWSを利用可能**だが、極力**無料枠で収まるよう**費用を抑えたい
- セキュリティは標準的な対応をしたい
- **プロトタイプは今日中**、2日程度で動く形にしたい
